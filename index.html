OpenClaw Workflow
Audio → Summary → Notion DB → DOCX

把錄音檔變成可交付的成果
（接近自動化的工作流）

你只要傳 mp3/m4a 或貼上雲端連結，OpenClaw 會逐步調用工具完成：下載 → 轉錄 → 摘要/決策/待辦 → 上傳 Notion DB → 產出 DOCX，最後回傳檔案路徑。

目標（Why）

把「會議錄音」變成「可追蹤、可分享、可複用」的資料資產
1
減少人工整理時間把聽錄音、抄筆記、貼 Notion 的重複工作交給工具鏈。
2
輸出一致、可比對用固定模板：摘要 / 決策 / 待辦 / Q&A / 風險。
3
交付更快Notion DB 一鍵入庫；同時產 DOCX 方便對外寄送或歸檔。

使用到的核心能力（What）

真實工具名稱 +（中文補充）給非資工同事看得懂
browser（網頁操作/下載） web_fetch / web_search（抓資訊） read / write / edit（檔案處理） exec / process（跑程式/背景任務） Notion API（入庫到資料庫） LLM（摘要/格式化）
輸入：mp3 / m4a / 雲端連結 輸出：Notion DB page + 摘要文件（.md）+ 交付文件（.docx）+ 本機路徑

Step 0 · Input
你提供什麼，我就從哪裡開始

輸入方式：檔案 or 連結

同一條流程支援兩種起點：直接上傳音訊檔，或提供雲端硬碟連結（Google Drive/Dropbox/OneDrive…）。

Option A：直接上傳檔案

Telegram/Discord 等聊天介面附檔
A1
message（收檔）使用者把 mp3/m4a 直接傳進來。
A2
write（落盤）存到本機工作目錄，並套用命名規則。

Option B：提供雲端連結

不必上傳大檔，貼連結就能處理
B1
browser（開連結）必要時登入/點下載（可半自動）。
B2
web_fetch（抓頁面資訊）若是可直連下載，會先解析連結型態。
B3
write（落盤）下載完成後同樣統一命名與資料夾結構。

Step 1 · Acquire & Organize
先把檔案變得「可管理」

命名規則與資料夾：讓後續全自動

先標準化「檔名、日期、專案、會議類型」，後面每一步都能靠規則串起來（減少人工決策）。

工具（Tools）

讀寫檔案 + 產生固定路徑
read（讀檔/看 metadata） write（寫檔/搬檔） exec（呼叫 ffmpeg/檢查音訊）
範例路徑（可依公司規則調整） /Users/openclaw/audio-inbox/2026-03-12_商務會談.m4a /Users/openclaw/whisperx-outputs/2026-03-12_商務會談.md /Users/openclaw/deliverables/2026-03-12_商務會談.docx

模板用途（Templates）

把「輸出格式」鎖定，讓不同會議也能一致
T1
摘要模板（Summary）背景 / 重點 / 結論（給快速閱讀）。
T2
決策模板（Decisions）決策事項、負責人、期限。
T3
待辦模板（Action Items）條列、可追蹤、可落到 Notion DB 欄位。

Step 2 · Transcribe
把聲音變成文字（後面才好摘要）

轉錄：Whisper / WhisperX

將音訊轉成逐字稿（含時間戳/說話人分段可選），輸出成 Markdown 方便後續摘要與引用。

工具（Tools）

在本機跑轉錄（可背景執行）
exec（跑 whisper/whisperx） process（追蹤背景工作） read（讀轉錄結果）
輸出（例） /Users/openclaw/whisperx-outputs/2026-03-12_商務會談.md （含：時間戳、段落、可能的 speaker labels）

品質控制（QC）

確保後續摘要不會「看錯」
Q1
抽樣檢查隨機挑 2~3 段對照音訊（專有名詞/數字）。
Q2
標記不確定字用 [unclear] 或備註，避免硬猜。
Q3
必要時二次處理降噪、音量正規化（ffmpeg）。

Step 3 · Summarize
把逐字稿變成「能做事」的摘要

摘要：LLM + 固定模板

LLM 不是只做「心得」，而是照模板產出：會議摘要、決策、待辦、風險、Q&A，方便直接入庫與派工。

摘要模板（可複用）

把格式變成規格：不同會議也能一致
輸出區塊（例） 1) Executive Summary（高層 30 秒看懂） 2) Key Points（重點條列） 3) Decisions（決策：事項/Owner/Due） 4) Action Items（待辦：可追蹤） 5) Risks & Open Questions（風險/未決議） 6) Appendix（必要引用逐字稿段落）

工具（Tools）

把「文字」轉成「結構化資料」
LLM（摘要/重寫/結構化） read（讀逐字稿） write（寫摘要 .md） web_search（查不確定名詞）
S1
結構化輸出把「人話」拆成欄位：日期/客戶/主題/決策/待辦。
S2
一致用字中文為主，中英文術語保留（避免翻錯）。

Step 4 · Deliver
Notion 入庫 + DOCX 交付

交付：上傳 Notion DB，並回傳 DOCX 路徑

把摘要拆成欄位寫入 Notion Database（可查詢/篩選/追蹤），同時產生 DOCX 方便寄給客戶或歸檔。

Notion DB（資料資產化）

同一套 schema，累積就會變成可搜尋的「知識庫」
Notion API（建立/更新頁面） write（存一份 md/docx） message（回覆連結與路徑）
Notion 欄位（例） - Date（日期） - Type（emba / 商務會談） - Participants（與會者） - Summary（摘要） - Decisions（決策） - Action Items（待辦） - Source Audio（原始音訊連結/檔名）

回傳給同事的訊息（可直接轉貼）

「看得懂、拿得到、找得到」

System Architecture
OpenClaw 怎麼把能力串起來

架構圖：從 Chat 到 Tools 再到交付

非資工視角：把它想成「協調員（Orchestrator）」負責決定下一步要用哪個工具，最後把結果整理成可交付物。

End-to-End（全流程模組）

真實工具名稱 +（中文補充）

Channels（訊息入口）

  • Telegram / Discord
  • File upload / Link
message（收/發訊息）

Orchestrator（流程協調）

  • 判斷輸入型態
  • 選擇下一個 tool
  • 套用模板
policy（規則/路由）

LLM（理解 & 產出）

  • 摘要 / 結構化
  • 語氣統一
  • 欄位映射
LLM（語言模型）

Deliverables（交付）

  • Notion DB page
  • DOCX 檔
  • 本機路徑回報
Notion API（入庫）write（產檔）

Acquire（取得檔案）

  • browser（網頁下載/登入）
  • web_fetch（解析頁面/抓直連）
browser（自動化點擊）web_fetch（抓內容）

Compute（本機處理）

  • exec（跑 whisper/whisperx）
  • process（背景任務）
  • read/write（輸入輸出）
exec（執行）read/write（檔案）
